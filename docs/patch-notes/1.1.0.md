# Cookie Jar 1.1.0

- Date: 2026-10-17
- Platform: Windows

## Briefing

Check GitHub for newer Windows versions and update from a pinned source snapshot.

## Changes

- Settings now includes Check for updates, displaying the installed version and newer versions found on GitHub main.
- Private repository access uses an existing GitHub CLI sign-in with repository read access; no GitHub token is stored by Cookie Jar. Public repositories have an unauthenticated HTTPS fallback.
- Offers source patch notes before downloading a pinned source snapshot and building it in an isolated temporary directory. No Git installation or Git checkout modification is required for updates.
- Installation waits for Cookie Jar to exit, verifies the built version and executable hash, keeps a previous-executable backup and rolls back on installation or immediate restart failure.
- Restart leaves Roblox sessions running and preserves application/account settings. Launcher automation pauses during restart and the session-only hardware override resets.

## Source

- `src/UpdateService.cs`, `src/MainWindow.Updates.cs`: GitHub checks, version comparisons and update UI.
- `scripts/install-update.ps1`: source staging, build verification, replacement and rollback.
- `build.ps1`: pinned source-archive build support and embedded installer.

## Validation

- Windows builds; automated version/revision checks and local source-build/install/rollback tests.
- Live authenticated GitHub main version, patch-notes and binary ZIP download checks.
- Existing hardware/RAM policy and release-workflow checks.

## Known limitations

- No interactive self-update or live Roblox test. Checks and downloads require internet access; GitHub rate limits and network errors are reported in the app.
- Source updates require Windows PowerShell and the .NET Framework C# compiler. Source snapshots must contain the update-aware build script (1.1.0 onward).
- Updates follow Windows main, including an explicitly offered alpha/beta version if that is the newer version on main. This does not update the separate macOS app.
- Backup and diagnostic staging files are retained for recovery. A launch that fails after the initial startup check is not automatically rolled back.

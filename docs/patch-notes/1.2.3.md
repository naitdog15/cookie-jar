# Cookie Jar 1.2.3

- Date: 2026-11-15
- Platform: Windows

## Briefing

Keep Windows account launches in separate Roblox clients

## Changes

- Hold the Roblox singleton mutex and reserve its routing-event name for Cookie Jar's lifetime, including between account launches. Stop a profile with a useful error if those guards cannot be reserved.
- Start saved accounts directly through the installed Roblox player with their individual authentication tickets, avoiding protocol-handler handoffs to a resident app or updater. Token validation and ticket authentication are preserved.
- Wait for the player started with that account's ticket to show a window for two seconds before reporting success. Stop launching further accounts if that player exits early or a previously tracked client exits during a launch.
- Protect tracked clients from idle-tray cleanup even when their windows are hidden or loading. Website launches use the same persistent guards.

## Source

- `src/MultiInstanceGuard.cs`, `src/Program.cs`: persistent guard ownership and cleanup on exit.
- `src/InstanceManager.cs`: launch preparation, client readiness and tray-cleanup protection.
- `src/TicketLauncher.cs`: direct player startup and profile failure handling.
- `tests/LaunchTests.cs`, `tests/build_launch_tests.ps1`: isolated launch regressions with unique kernel-object names and simulated clients.

## Known limitations

- No live six-account Roblox test has been performed. Simulated clients do not establish server-side login or game-join success.
- Keep Cookie Jar running while using multiple accounts. If Roblox requires an update, update it once with all games closed before retrying the profile.

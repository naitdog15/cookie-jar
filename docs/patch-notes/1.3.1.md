# Cookie Jar 1.3.1

- Date: 2026-11-15
- Platform: Windows

## Briefing

Preserve account tracking and correct Windows launch preparation edge cases

## Changes

- Track and associate each account with its exact player process immediately after startup. Cancellation, a readiness timeout, or an earlier client's exit leaves already-started players manageable and prevents duplicate account launches on retry.
- Keep readiness separate from tracking and reuse an already-adopted player card when launch/adoption paths meet.
- Skip hidden tray processes during startup adoption. Keep already-tracked games protected even when hidden, and only clean up positively identified hidden `--launch-to-tray` clients; process age alone no longer triggers termination.
- Prefer the current user's registered Roblox handler/environment, then machine registrations, over leftover install folders. When registration is unusable, compare all standard install roots for the newest player.
- Recheck running clients immediately before optional cache cleanup so a client starting during launch preparation keeps its cache.
- Recover safely when the multi-instance guard thread cannot start, including retry and application exit.
